# Doxygen Documentation Strategy & Assessment

This document provides recommendations and guidelines for generating documentation directly from embedded Doxygen tags within the repository while keeping all generated documentation artifacts untracked in Git.

---

## Strategy Overview

To build API and code documentation directly from repository source code using Doxygen tags (e.g., `@file`, `@brief`, `@param`, `@return`, `@author`, `@date`, `@note`) without tracking build artifacts in version control:

1. **In-Code Standard**: Maintain Doxygen-formatted docstrings and header comments in source files (`gridgen/*.py`).
2. **Doxygen Configuration (`Doxyfile`)**: Maintain a single configuration file (`Doxyfile`) in the repository root that defines source inputs, filters, and build output directories.
3. **Repository Cleanliness (`.gitignore`)**: Exclude all documentation build output directories (e.g., `docs/html/`, `docs/latex/`, `docs/xml/`) from Git tracking.
4. **Local Build Drivers (Optional)**: Provide an optional helper script or Makefile target for developers wishing to preview documentation locally before pushing code.
5. **CI/CD Deployment (GitHub Actions)**: Build documentation in temporary runner environments on push or release and publish HTML directly to **GitHub Pages** (or upload as pipeline artifacts) without committing generated files back into main repository branches.

## Frequently Asked Questions & Technical Clarifications

### 1. Is the local helper script (Section 4) required if documentation generation is part of the CI/CD workflow?

**No, it is strictly optional.**

- **In CI/CD:** The GitHub Actions runner executes `doxygen Doxyfile` directly during pipeline execution. No helper script is required on the server.
- **Purpose of local script:** The helper script is provided solely for local developer convenience so developers can generate and inspect HTML documentation locally on their workstation before opening a Pull Request or pushing changes.

---

### 2. Does GitHub Pages need to be set up explicitly in the repository settings?

**Yes.** GitHub Pages must be explicitly enabled once in the GitHub repository settings for the automated action to publish:

1. Navigate to repository **Settings** → **Pages**.
2. Under **Build and deployment**, set **Source** to **GitHub Actions**.
3. Under Workflow Permissions (Settings → Actions → General), ensure workflow permissions are set to **Read and write permissions** so the GitHub Actions runner can publish the page artifacts.

*Note: You do NOT need to create or manage a `gh-pages` branch when using GitHub Actions deployment (`actions/deploy-pages@v4`). GitHub Pages receives the deployed site artifact directly from the workflow run.*

---

### 3. Why would `index.html` or generated documentation pages give a 404 error on GitHub Pages?

GitHub Pages processes uploaded site artifacts with Jekyll by default. Doxygen generates many files and directories with leading or multiple underscores (e.g. `____init_____8py.html`, `_dep.png`), which Jekyll ignores during rendering. This causes resources and `index.html` to fail to load, resulting in 404 errors.

**Solution:** Bypassing Jekyll processing by creating an empty `.nojekyll` file inside `docs/html/` (`touch docs/html/.nojekyll`) before uploading artifacts via `actions/upload-pages-artifact`.

---

### 4. Why might `workflow_dispatch` not be accessible or visible in GitHub Actions?

GitHub Actions only displays `workflow_dispatch` (manual run button) in the Actions tab UI if the workflow YAML file exists on the repository's **default branch** (e.g., `main`). If a workflow exists solely on a feature or non-default branch, the manual run option will not appear until the workflow file is merged into the default branch.

---

### 5. What is the entry HTML file for GitHub Pages?

The entry HTML page generated by Doxygen is **`index.html`** located inside the output folder (`docs/html/index.html`).

- **Root URL mapping:** When deploying the contents of `docs/html/` as the site root artifact via `actions/upload-pages-artifact` (specifying `path: 'docs/html'`), GitHub Pages automatically serves `index.html` as the default landing page URL (e.g., `https://<org>.github.io/<repo>/index.html` or `https://<org>.github.io/<repo>/`).
- **Main page customization:** Setting `USE_MDFILE_AS_MAINPAGE = README.md` in `Doxyfile` instructs Doxygen to render `README.md` as the home panel inside `index.html`.

## Step-by-Step Implementation Guide

### 1. Configure `.gitignore` to Exclude Output Artifacts

Add the build output locations to `.gitignore` so that running doc generation locally never shows untracked files in `git status`:

```gitignore
# Doxygen documentation output directories
/docs/html/
/docs/latex/
/docs/xml/
/docs/man/
/docs/build/
*.doxytag
```

---

### 2. Doxygen Configuration (`Doxyfile`)

Create a standard `Doxyfile` in the repo root directory (generated using `doxygen -g Doxyfile` and adjusted for Python):

Key configuration properties to set:

```ini
# Project Identification
PROJECT_NAME           = "WW4 Gridgen"
PROJECT_NUMBER         = "3.0.0"
PROJECT_BRIEF          = "WAVEWATCH III / WAVEWATCH IV Grid Generation Package"
OUTPUT_DIRECTORY       = docs

# Source Code Parsing Settings
INPUT                  = gridgen README.md
RECURSIVE              = YES
FILE_PATTERNS          = *.py *.md
EXTENSION_MAPPING      = py=Python

# Extraction Settings
EXTRACT_ALL            = YES
EXTRACT_PRIVATE        = YES
EXTRACT_STATIC         = YES
OPTIMIZE_OUTPUT_JAVA   = YES   # Better formatting for Python class/function structures

# Output Formats
GENERATE_HTML          = YES
HTML_OUTPUT            = html
GENERATE_LATEX         = NO    # Set to YES if PDF manual generation is needed
GENERATE_XML           = NO

# Markdown & Indexing Options
USE_MDFILE_AS_MAINPAGE = README.md
```

### 4. Local Build Helper Script (Optional)

An optional executable script (e.g., `build_docs.sh`) for developers wishing to preview documentation locally before committing:

```bash
#!/usr/bin/env bash
# Build Doxygen documentation locally without tracking output
set -e

SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
ROOT_DIR="$(dirname "$SCRIPT_DIR")"

cd "$ROOT_DIR"

if ! command -v doxygen &> /dev/null; then
    echo "Error: doxygen command not found. Please install Doxygen."
    exit 1
fi

echo "Generating Doxygen documentation..."
doxygen Doxyfile

echo "Documentation generated successfully at docs/html/index.html"
```

### 5. CI/CD Integration via GitHub Actions (GitHub Pages)

To make generated documentation accessible online without storing built HTML in the main branch, use a GitHub Actions workflow (`.github/workflows/docs.yaml`):

```yaml
name: Generate Documentation

on:
  push:
    branches: [ main, develop, "feat/*" ]
  pull_request:
    branches: [ main, develop, "feat/*" ]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: "pages"
  cancel-in-progress: false

jobs:
  build-docs:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Install Doxygen
        run: |
          sudo apt-get update
          sudo apt-get install -y doxygen graphviz

      - name: Build Doxygen Documentation
        run: doxygen Doxyfile

      - name: Disable Jekyll for GitHub Pages
        run: touch docs/html/.nojekyll

      - name: Upload Artifact for GitHub Pages
        uses: actions/upload-pages-artifact@v3
        with:
          path: 'docs/html'

  deploy-docs:
    needs: build-docs
    if: github.event_name != 'pull_request' && github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```

## Key Benefits
1. **Zero Repository Bloat**: Git tracks only source code, `Doxyfile`, and the workflow. Built HTML/PDF files are never committed to your repository.
2. **Always Up to Date**: Documentation updates automatically whenever source code comments change.
3. **Continuous Deployment**: Output HTML is automatically rendered and hosted via GitHub Pages (or attached as downloadable CI artifacts) on every push or release.
